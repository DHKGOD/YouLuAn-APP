# 組員入門：用自己的 agent 讀懂有路安

目標是讓每位組員能解釋自己的部分、在自己的電腦試用，並交回看得懂的修改。先學一條完整流程，不需要第一天讀完所有檔案。

## 1. 先選你要做什麼

| 目標 | 準備方式 |
|---|---|
| 先理解程式、準備提案 | 看 README、程式閱讀指南和資料表圖，再把相關檔案提供給聊天工具 |
| 在電腦實際操作 | 下載專案、準備工具，依 README 啟動自己的資料庫與 API |
| 讓 agent 查程式、執行測試 | 本機 Codex 或 Claude Code 開啟專案資料夾 |
| 改程式交回小組 | Fork 或取得協作者權限，開自己的分支，測試後交 Pull Request |

ChatGPT／Claude 是協助學習與開發的工具，專案仍在你自己的電腦執行。單純貼 GitHub 網址不代表聊天工具已下載所有檔案、啟動 PostgreSQL 或連到你的手機。

## 2. 取得自己的副本

照 README 的 clone 指令下載，或從 GitHub 選 Code → Download ZIP。請記住你實際下載的資料夾位置，不要照抄別人電腦的路徑。

只閱讀不用開分支。準備修改前，先在專案資料夾執行：

```powershell
git status
git switch -c member/你的工作名稱
```

ZIP 副本沒有 Git 紀錄；要共同開發建議改用 clone。沒有共同倉庫寫入權限時，先在 GitHub Fork 到自己的帳號，再 clone 自己的 Fork。

## 3. 用 ChatGPT／Codex

只想學習時，可以提供 README、docs/code-guide.md 與你負責的程式檔，請它用實際內容說明。若工具無法讀 GitHub，就自行提供檔案，別把「沒有讀到」當成「程式沒有做」。

需要實際讀寫檔案與測試時，使用本機 Codex：登入自己的帳號，開啟你下載的專案資料夾，再送出下方提示詞。也可使用 Codex CLI 或編輯器擴充功能。介面會隨版本調整，以[官方入門](https://learn.chatgpt.com/docs/quickstart)為準。

雲端 agent 適合讀程式或在其環境測試；它不能直接取代你的 Windows、區網資料庫與 Android USB 實機。這個專題的第一次完整啟動建議先在本機完成。

## 4. 用 Claude Code

依[Claude Code 官方入門](https://code.claude.com/docs/en/quickstart)安裝並登入自己的帳號。終端機進入專案資料夾後執行 claude；它會依需要讀取專案檔案。可用的帳號方案與額度依服務規定，不需要向組長索取登入資訊。

本專案 CLAUDE.md 會引用 AGENTS.md。即使是第一次使用，也請明確要求 agent 先讀這些規則，再依自己的電腦狀態處理。

## 5. 第一段：請它當助教

整段貼上即可：

```text
我是有路安資料庫專題的組員，請用繁體中文當我的程式助教。
先讀 README.md、docs/code-guide.md、docs/team-agent-guide.md、
AGENTS.md、HANDOFF.md，再確認目前檔案及 git status。
現在只閱讀，不修改、不安裝、不啟動服務。

先教我「查附近危險路口」這一條流程：
畫面從哪個檔案開始？送哪個 API？SQL 查哪些資料表？
回傳的資料如何變成地圖上的標記？
每次只教一小段，附實際檔名與關鍵函式，問我一題確認理解。
沒有讀到的內容請說不知道，不要自己補功能或測試數字。
```


## 6. 第二段：請它檢查自己的環境

```text
我要在自己的 Windows 電腦試用這份專案。
請先讀 README 與啟動腳本，檢查 Git、uv、Python 3.11、Node.js、
PostgreSQL 是否可用，以及 5432 和 8000 是否被其他服務使用。

先列出已具備與缺少的項目，不要改我的其他專案、系統設定或資料庫。
需要安裝工具或做會影響其他資料的操作時，先說明用途與官方來源。
這是我自己的副本，請依本機狀態設定，不要沿用原作者的路徑、IP、帳密。
不要讀出、回貼或提交 .env 的秘密值。
```

如果電腦已經有別的 PostgreSQL，不要為了這份專題停止或重建它。先讓 agent 檢查，再選擇獨立連接埠／資料目錄，或依部署文件使用外部資料庫。

## 7. 第三段：啟動與驗收

工具準備好、你同意在本副本建立資料後再貼：

```text
請依 README 啟動這份專案，可以在這個副本建立自己的資料庫、
下載官方事故資料、匯入並訓練專題模型。
不要動其他專案，不用付費服務，也不要上傳 .env 或資料庫。

完成後幫我確認：
1. /api/health 的 status 是 ok，資料庫可用。
2. 瀏覽器能看到地圖與危險路口清單。
3. 能用 SQL 說明事故列數與當事人列數的差別。
4. AI 模型已載入；若訓練失敗，請保留錯誤並說明哪些功能仍可用。
5. 印出我的手機同 Wi-Fi 應使用的 API 網址。
每一步回報實際結果，不要只列操作建議就說成功。
```

首次需要下載資料與訓練，等待時間依網路和電腦而定。即時天氣不是首次驗收的必要條件，也不需要 OpenAI／Anthropic API key。

## 8. 請它協助你負責的部分

```text
我負責的是【填入你的工作，例如資料來源與資料表介紹】。
請從現有程式與文件找證據，教我：
資料怎麼來、為什麼這樣設計、對應哪個檔案、可以怎麼操作展示。
最後給我五個老師可能會問的問題，先讓我自己回答再幫我修正。
不要把規劃中的功能說成已完成，也不要修改 AI 評估數字。
```

改功能時改用這段：

```text
我要修改【具體功能】，先看 git status 並開自己的分支。
先說明會碰哪些檔案，再完成修改與合適的測試。
保留其他人未完成的改動，不要一起提交。
最後更新 TASKS.md 與 HANDOFF.md，告訴我改了什麼、怎麼測、還沒驗什麼。
不要自行推送、合併、重建資料庫或安裝到手機。
```

## 9. 排錯時提供什麼

提供執行的指令、錯誤文字、最後成功步驟，以及自己的工具版本。伺服器紀錄在 logs/，可以選必要片段；先遮住金鑰、密碼、完整連線字串與個人資料，不要整包上傳。

常見區別：能看到地圖但沒有底圖，可能是外部圖磚連線；能看到首頁但沒有 AI，可能是模型未載入；只有手機連不上，則先看 Wi-Fi、目前 IP、伺服器是否開著與連線是否被阻擋。讓 agent 查證，不要一開始就叫它關閉防毒。

## 10. 分享設定的原則

公開倉庫只提供 .env.example 範本，真正的 .env、API key、資料庫、手機識別碼與個人定位不分享。GitHub 看得到程式，不代表組長的電腦或資料庫已授權給你連線。

本公開副本不附原作者的 .mcp.json、.codex 私人設定或舊機器交接紀錄。MCP 是選用工具；先能讀程式與啟動 API，再視需要依自己的環境設定，不用為了學專題先裝一堆外掛。
